# 需求澄清：显式启用工作流

## 用户输入

- “没有使用工作流的skill 默认不使用工作流，只有用户声明时才使用”
- “修改工作流”

## 目标与范围

调整 t-flow 的触发规则：默认不启用工作流；只有用户明确调用 `/t-flow`、明确要求使用 t-flow，或明确要求继续某个已识别的 t-flow 变更时才启用。删除仅凭项目中存在未归档变更和用户说“继续”就自动进入 t-flow 的规则。

同步修改入口 Skill 的触发描述与自动节点检测说明，以及 README 中使用说明；补充或调整现有回归测试，防止隐式触发规则重新出现。

## 不做事项

- 不修改 8 个节点的执行顺序、确认门禁、状态隔离和证据机制。
- 不禁止用户在明确意图下恢复未归档变更。
- 不调整其他无关 Skill 的触发规则。

## 角色与权限

- 用户：决定是否显式启用或恢复工作流，并确认各阶段产物。
- 执行 agent：未获明确声明时直接处理任务；获得明确声明后才加载并推进 t-flow。

## 验收条件

- AC-01-1：入口 Skill 不再把“存在未归档变更 + 用户说继续”描述为自动触发条件。
- AC-01-2：入口 Skill 明确说明默认不启用，只有用户明确声明使用或恢复 t-flow 时才启用。
- AC-01-3：README 的使用说明与入口 Skill 一致，不再引导隐式续跑。
- AC-01-4：项目现有回归测试及新增的相关静态检查通过。
