# PRD：精简验证工作流

- change-id：`lean-verification-workflow`
- 上游：`clarify-log.md`（用户确认：“按这个范围继续修改。”）
- 目标：在不取消验收门禁和证据约束的前提下，减少重复测试、过细 AC 和不必要的浏览器组合验证。

## 需求与验收标准

| 需求 | 验收编号 | 前置条件与操作 | 预期结果 | 验证方式 |
|---|---|---|---|---|
| REQ-01 控制验收门禁粒度 | AC-01-1 | 阅读需求与设计指导，模拟包含内部边界和排列组合的功能拆分 | 只把用户可观察、需要交付门禁的结果定义为必测 AC；内部边界优先进入共享自动化测试集，不默认展开成大量独立 AC | static |
| REQ-02 采用默认精简验证策略 | AC-02-1 | 阅读后端与前端验证指导 | 后端以单元测试和数据正确性为主；前端默认为构建、少量组件测试、至多 1 条核心 E2E 与必要人工冒烟；无界面变更不要求 E2E | static |
| REQ-03 消除跨层重复验证 | AC-03-1 | 同一行为已由合适层级覆盖，准备编写其他层级测试 | 不重复执行全部角色、对象和规则组合；相关 AC 可共享一次真实测试执行；已声明的真实权限、数据或界面行为仍须有效验证 | static |
| REQ-04 保持报告可追溯 | AC-04-1 | 一个测试套件覆盖多条相关 AC，填写测试模板与报告 | 模板和 README 说明多 AC 映射；报告仍逐条记录 AC 状态、证据和未测项，不以套件汇总通过数掩盖未测项 | static |
| REQ-05 保持工作流兼容与证据约束 | AC-05-1 | 在既有变更和新变更上使用修改后的工作流 | 状态机、用户确认门禁、AC 覆盖、`not_run` 阻断、证据完整性和输入过期行为不变；历史变更不被自动降低验收标准，项目回归测试通过 | build |

## 角色与授权边界

- 用户负责确认验收范围，以及任何对既有 AC 或验证方式的调整。
- 执行 agent 可选择最低有效验证层级并合并重复场景，但不能自行删除已确认 AC、将必测项改为可选或将未测项写成通过。
- 本变更不新增业务角色、数据权限或写入口。

## 页面、接口与交付边界

| 能力 | 页面/路由或嵌入位置 | 接口 | 验收编号 |
|---|---|---|---|
| 精简验证指导 | t-flow 的需求、设计、验证 Skill 与测试模板，无独立页面 | 不新增业务接口；沿用现有 `yt.mjs` 与 `acceptance` 数组 | AC-01-1 ～ AC-05-1 |

交付包括入口说明、相关节点指导、测试模板、README 与必要回归断言。不引入测试框架或业务运行时依赖。

## 不做事项与未决问题

不做事项：

- 不取消任何用户确认门禁或全部 AC 必须通过的要求。
- 不自动修改历史变更的验收标准。
- 不降低证据真实性、完整性和输入过期检查。
- 不要求所有项目采用同一测试工具。

未决问题：无。
