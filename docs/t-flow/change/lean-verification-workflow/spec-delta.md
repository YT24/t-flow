# Spec Delta：精简验证工作流

## ADDED

### 默认精简验证策略

**场景：后端逻辑与持久化验收**

- 纯逻辑优先由单元测试验证。
- 涉及持久化时验证最终数据、约束、事务或审计结果。
- 不要求通过浏览器重复验证后端已经覆盖的规则和组合。

**场景：前端验收**

- 默认使用构建/静态检查、少量共享组件测试、至多 1 条核心链路 E2E 和必要人工冒烟。
- 无界面变更不要求 E2E。
- 浏览器验证代表性用户链路，不执行全部角色、对象和规则排列组合。

### 共享测试覆盖多条验收标准

**场景：一次真实测试执行覆盖多条相关 AC**

- 用例通过 `acceptance` 数组声明全部相关 AC。
- 测试报告保留每条 AC 的状态、证据和未测说明。
- 共享测试不得减少任何已确认 AC 的有效验证。

## MODIFIED

### 验收标准拆分

原行为：内部边界、普通异常分支和排列组合容易全部成为独立必测 AC，造成门禁数量膨胀。

新行为：只把用户可观察、需要交付门禁的结果定义为必测 AC；内部边界优先进入共享自动化测试集。

### 验证层级选择

原行为：验证指导强调真实行为验证，但未明确限制跨层重复测试，容易将后端组合重复搬到浏览器。

新行为：同一行为只在一个最低且有效的层级验证；真实权限、数据或界面行为被声明为 AC 时仍须使用能证明该行为的方式。

### 测试报告组织

原行为：按用例和 AC 罗列结果，未明确一次套件与多条 AC 的映射方式。

新行为：按真实测试套件组织执行并映射到 AC，同时保留逐 AC 可追溯状态。

## REMOVED

无移除状态机、用户确认、必测 AC 覆盖或证据校验行为。
