# ADR：通过指导与模板精简验证，不改变运行器契约

## 背景

测试耗时主要来自过细 AC、跨层重复验证和重复启动环境。现有运行器已支持一个用例的 `acceptance` 数组覆盖多条 AC，因此可以为减少重复执行而修改协议，也可以仅调整需求、设计和验证指导。

## 可选方案

1. 修改协议和证据模型，引入新的共享证据或测试配置。
2. 保持运行器契约不变，使用现有多 AC 映射能力，修改 Skill、模板、README 和回归测试。

## 决定

采用方案 2。本次优化测试组织方式，不引入新的共享证据模型，也不改变协议指纹。

## 理由与影响

- 可直接复用现有多 AC 覆盖、证据和状态校验，降低实现与迁移风险。
- 未归档和历史变更不会因协议变化被自动迁移或降低验收标准。
- 代价是运行器仍只校验结构与证据，不能自动判断测试是否重复或语义是否充分；精简策略需要执行 agent 遵循，并由用户继续确认验收范围。
