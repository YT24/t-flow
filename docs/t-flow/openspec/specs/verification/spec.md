# t-flow 验证与验收规范

## Requirements

### Requirement: 验收标准保持精简且可追溯

只把用户可观察、需要独立交付门禁的结果定义为必测 AC。内部边界、普通异常分支和角色、对象、规则排列组合优先进入共享自动化测试集，不默认逐组合创建 AC。

#### Scenario: 功能包含多个内部边界

- 执行 agent 将需要用户验收的可观察结果定义为 AC。
- 内部边界由共享自动化测试集覆盖，不自动增加独立交付门禁。
- 所有已定义 AC 仍须在 `verify/test-results.json` 中逐条关联已通过的必测用例。

### Requirement: 使用最低有效验证层级

同一行为只在一个能够证明其正确性的最低有效层级验证，不在其他层级重复相同组合。

#### Scenario: 后端逻辑与持久化验收

- 纯逻辑以单元测试为主。
- 持久化验证最终数据、约束、事务或审计结果。
- 已通过后端覆盖的规则和组合不再通过浏览器全量重复。

#### Scenario: 前端验收

- 默认使用构建或静态检查、少量共享组件测试和必要人工冒烟。
- 人工冒烟只验证代表性用户链路和前端自身行为。

#### Scenario: AC 声明真实行为

- 已确认 AC 明确声明真实权限、数据或界面行为时，必须使用能够证明该行为的验证方式。
- 精简策略不得将真实行为验收替换为无意义静态检查，也不得将 `not_run` 视为通过。

### Requirement: 小改动默认只执行受影响测试

plan.md 必须建立改动模块、受影响 AC 与最小验证命令的映射；execute 和 verify 不因方便而默认运行全量回归。

#### Scenario: 局部改动

- 只运行映射到的测试文件、套件或名称模式，并覆盖全部受影响 AC。
- 局部文档、模板、文案、单页面展示或样式改动不得触发全量测试。

#### Scenario: 确需全量回归

- 仅限共享核心状态机/权限、数据迁移、构建依赖、用户明确要求或影响范围无法可靠确定。
- 在 plan.md 与测试报告中写明全量原因；验收覆盖与证据要求保持不变。

### Requirement: 共享真实测试覆盖多条相关 AC

一次真实测试执行可以覆盖多条相关 AC，避免为每条 AC 重复启动相同环境或浏览器。

#### Scenario: 一个套件映射多条 AC

- 用例在 `acceptance` 数组中完整声明相关 AC，并记录 `method`。
- 每条 AC 都由 `required:true`、`status:passed` 的用例覆盖。
- 报告逐条记录 AC 状态、实际断言、证据和未测说明，套件汇总通过数不能掩盖未测项。
- 证据继续由 verify 阶段独立执行生成，不能复制其他用例或复用 execute 证据。

### Requirement: E2E UI 验证由用户选择环境并隔离提交边界

默认验证不主动新增 E2E；用户明确要求或 AC 必须真实浏览器操作时，先由用户选择本地隔离服务或开发环境。

#### Scenario: 本地启动服务验证

- 服务不注册到共享 Nacos，或使用独立 namespace/group，测试直连本地实例。
- 数据库、MQ 和端口隔离，同一 `run` 入口负责启动、断言与清理。

#### Scenario: 发布到开发环境验证

- 只精确提交并推送当前任务实现代码，禁止 `git add -A`；测试脚本、工作流产物、临时文件和凭证不得进入提交。
- 无法分离其他改动时停止，由用户整理工作树；推送不等于部署完成，须确认开发环境运行的是该提交。
- 用户提供访问地址和测试专用账号密码后再执行；凭证只在运行时使用，不进入脚本、命令行、日志、证据或仓库。
- E2E 由 `run` 真实执行，逐 AC 绑定证据；历史实例在线时不得仅凭 HTTP 200 认定本次实现通过。

#### Scenario: 同一页面包含多条相关 AC

- 共用一个 Playwright 套件与浏览器会话，一次启动/登录后逐条断言，不为每条 AC 单独写脚本或重启浏览器。
- 构建/部署按相关改动批次执行，不在每个小步骤后重复上传开发环境。
- 能由构建或组件测试证明的页面存在、字段渲染和简单五态不重复跑浏览器；成功截图不逐张阅读。

### Requirement: 保持工作流门禁与证据兼容

精简验证只调整测试组织和指导，不改变工作流状态机与证据契约。

#### Scenario: 新变更或历史变更使用工作流

- 用户确认门禁、必测 AC 覆盖和 `not_run` 阻断保持有效。
- 证据输入绑定、日志、runId、完整性及输入过期检查保持有效。
- 历史变更的验收标准不被自动修改；调整既有 AC 或验证方式必须重新确认。
