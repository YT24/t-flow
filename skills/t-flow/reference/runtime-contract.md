唯一运行入口 scripts/yt.mjs，读取同目录 reference/workflow-protocol.json（运行时只消费其中列出的字段；编辑该文件即变更协议指纹）。项目根使用 TFLOW_RUN_ROOT 或 cwd。运行 help 查看接口；check 只读并检查产物、任务和测试，待确认时返回 ARTIFACTS_READY；advance/archive 额外要求确认有效后才能推进；协议变更后 migrate；验证循环超限后 decide。UI 设计 Skill 见协议 uiSkillRouting（主 ui-ux-pro-max、兜底 frontend-design，均随包分发）：ensure-skills 把缺失的 Skill 装到项目 .agents/skills/ 并在 .claude/skills/ 建符号链接（Claude 与 agent 两条发现路径都可命中），ui-routing 查看可用性，ui-use [Skill名] 在 ui 节点记录本次所用；doctor 会校验 Skill 可用性、分发内容是否齐备，以及 ui.md 是否已记录所用 Skill。
ui.md 必须含 ui-scope 声明块（mode: new|change、files、affected），把「用户确认的界面」与真实文件绑定：check 校验其存在与路径真实性（mode=change 时必须列 affected），run 把 files 与 affected 强制计入证据输入，改动已声明的界面文件会使证据过期。存量项目若涉及样式/主题改动，须把样式文件列入 files 或 affected——UI 变更未绑定任何样式文件时 run 会告警（见协议 uiChange.styleGlobs）。
