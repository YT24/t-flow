# 验证与结果（execute/verify 首次读取）

按 plan 的影响范围选择最低有效验证层级，只运行相关测试与直接依赖回归。全量仅限核心状态机/权限、迁移、构建依赖、用户明确要求或无法确定影响范围。相同输入与环境的构建只执行一次。

最终验证使用 `run <id> --expect <成功条件> --reject <失败条件> -- <命令>` 真实执行测试。run 返回退出码、状态、耗时与断言摘要，并在现有 state.json 中覆盖保存每个任务/套件的最新状态、关联 AC 和输入指纹，不写 logs/、evidence/、attempts/ 或其他执行记录文件。无需为登记重复测试，不需要证据引用或 reuse 对象。包装器断言数不是测试用例数，用例数只取测试框架实际统计。

execute 的 id 为任务 id；modules 明确实现范围，执行时路径须存在。最新任务验证通过且输入未变后 `task <id> done`。verify 按真实执行结果填写报告；不能用任务 done、构建成功、echo OK 或打印数量替代业务 AC 验收。Bash 自动启用 errexit/pipefail；多个 --expect 表示全部满足，A|B 只是任选。

同一次真实套件可覆盖多条相关 AC，不为每条 AC 重复执行。只有确认输入与环境未变才沿用已执行结果；代码、测试、配置或环境变化时重跑受影响套件。集成环境先预检，无法执行写 not_run。仅真实浏览器验收需要时读取 e2e.md，不主动新增 E2E。

测试报告只保留结果：逐条 AC 的 passed/failed/not_run、失败或未测原因及总结果。verify/test-results.json 仅需 changeId 与 tests，各用例包含 id、required、status、acceptance；id 包含相关 REQ 编号。每个 REQ 与全部 AC 都须有通过的必测用例；可选或未测用例不满足覆盖，任何 failed 或必测 not_run 阻断验收。不得降低已确认验收范围。

不生成或引用证据与日志，不在报告抄录命令、运行编号或原始输出。手工测试按实际观察记录。凭证不得写入产物，run 拒绝含疑似凭证的命令，输出命中时仅显示规则名并返回失败；普通失败则在终端显示最多 4000 字符的错误片段，错误片段不写入状态或报告。

失败后 reopen execute，修复并仅重跑失败及受影响套件。验证修复回退超过三次时展示失败情况，由用户决定后 decide。异常恢复才读 recovery.md。

## 结果门禁

run 开始前将该任务/套件置为 not_run，结束后覆盖为 passed 或 failed；失败或中断不得由手改报告消除，须在对应阶段重跑同一任务/套件。每个必测通过用例须匹配已有最新通过结果（同 id，或同一任务/套件覆盖其全部 acceptance），报告不增加引用字段。一个真实套件可覆盖多条相关 AC。

指纹覆盖任务 modules、显式 --input（必须包括实际测试脚本、测试配置与依赖）、现有上游文档与常见依赖清单；目录包含新增/删除文件，忽略 .git、.t-flow、node_modules 与常见构建输出。验证期间输入变化也记为失败。源码变更后 reopen execute、重跑受影响任务；测试脚本或配置变更后重跑对应套件。新会话从现有状态恢复，不创建日志、证据或执行历史文件。

普通 Shell 可调试，最终验证直接经 run 执行并更新状态，不为每条 AC 重复执行。手工测试仍按真实观察填写；其可执行验证入口经 run 完成，不能用 echo、占位脚本或仅检查记录存在代替真实验收。外部环境变化仍需主动重测。

## 独立快速修复

显式 /t-flow-fix 使用 fix <任务id> [--repair <项目内 Bash 脚本>] [验证参数] -- <测试命令>。修复脚本和验证在同一 change 锁内执行；共用验证结果、输入指纹与失败阻断，只刷新该任务及已有完整覆盖的关联套件。当前节点、完成节点、任务状态和审批原文不变；旧交付验收随验证输入变化失效。修复脚本禁止改写 change 文档或状态，契约变化必须回到对应阶段确认。只同步已有结果报告，不生成或追加 fix-log.md，不生成 logs/evidence。
